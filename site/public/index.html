resAPI

Type-safe HTTP contracts for ReScript

Define your API once. Share types and validation between clients and servers, on Hono, Express or Cloudflare Workers.

Get started GitHub npm
npm install @resapi/core @resapi/hono @resapi/sury hono sury sury-ppx
npm install @resapi/core @resapi/express @resapi/sury express sury sury-ppx

1. Describe the endpoint

A contract names the route, the params, the response and the errors the endpoint can return. Clients and servers both import it.

AccountApi.res

open ResApi

@schema type params = {id: string}
@schema type account = {id: string, name: string, balance: float}
@schema type accountError = | @as("not_found") NotFound

let getAccount =
  Endpoint.get(
    "/accounts/:id",
    ~params=SuryCodec.make(paramsSchema),
    ~response=SuryCodec.make(accountSchema),
  )->Endpoint.withErrors(SuryCodec.make(accountErrorSchema), ~status=error =>
    switch error {
    | NotFound => 404
    }
  )

2. Implement it

The handler receives decoded, validated params. Values returned from the handler must conform to the API contract or the compiler will raise an error.

App.res

open ResApiHono

let app: Router.t<unit> =
  Router.make()
  ->Router.register(
    AccountApi.getAccount->EndpointHandler.make(async (_ctx, {params}) =>
      switch accounts->Dict.get(params.id) {
      | Some(account) => Ok(account)
      | None => Error(NotFound)
      }
    ),
  )

// A router is a Hono app, so it is already a Cloudflare Worker.
let default = app

ExpressApp.res

open ResApiExpress

let app =
  Router.make()
  ->Router.register(
    AccountApi.getAccount->EndpointHandler.make(async (_req, {params}) =>
      switch accounts->Dict.get(params.id) {
      | Some(account) => Ok(account)
      | None => Error(NotFound)
      }
    ),
  )

Server.res

// A router is an Express app, so Express middleware works as is.
let server = ExpressApp.app->ResApiExpress.Router.listen(3000, () => Console.log("Listening on :3000"))

3. Call it

The client builds the URL, validates the response, and returns a strongly typed result.

AccountClient.res

switch await client->Client.call(AccountApi.getAccount, ~params={id: id}) {
| Ok(account) => account.name
| Error(Application({error: NotFound})) => "no such account"
| Error(_) => "request failed"
}

Why resAPI

  • One definition

    Server handlers and client calls take their types from the same contract value, with no generated code.

  • Validated at both ends

    Requests are decoded before your handler runs. Responses are decoded before your code sees them.

  • Typed application errors

    Each endpoint lists the errors it can return, such as NotFound or AccessDenied, and their HTTP statuses. Clients handle them separately from network and validation failures.

  • Native frameworks

    A router is a Hono or Express app, so their middleware works as is.

Packages

@resapi/core Contracts, codecs and the typed client. Depends only on Fetch.
@resapi/hono Hono adapter, for Node and Cloudflare Workers.
@resapi/express Express 5 adapter.
@resapi/sury Sury schemas as codecs. Hand-written codecs work too.
